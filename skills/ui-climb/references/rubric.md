# UI rubric

Score references only on what their shots show.

**Scale**: 1 to 10 in half points. 5 is functional but generic, 7 a good shipping app, 9 best in
class.

## General rows

Their median is the climb's target score.

| Row | Question |
| --- | --- |
| Typography | Type scale, weights and line lengths; how readable long text is |
| Hierarchy | Whether the eye lands first on what matters: the latest state over history |
| Spacing and density | Rhythm and grouping; how much fits without feeling cramped |
| Colour and contrast | Calm palette, legible secondary text, accent colour only where it means something |
| Iconography | Icons, avatars and symbols: consistent, sized to their text, never decoration |
| Consistency and polish | One way to do each thing; alignment, insets and timing that match across screens |
| Clarity | Whether someone new understands what each element is and what to do next |

## Owner's cases

Reported apart from the general rows, so polish cannot hide a product regression. Written with
the owner for each climb, as questions with anchors. Examples that worked:

- **One assistant**: "Does the screen look like one chat with one entity? 3: bot marketplace, 5:
  neutral, 7: clearly one assistant, 9: it never occurs to you that more than one thing works."
- **Single product** (web against iOS): "Do web and iOS look like one product in theme and
  components?"
- **Match** (against one reference site): "How closely does this state match the reference's
  same state in layout, type and spacing? 10 is indistinguishable."

A short owner brief is enough to start from: "One agent, looks like a single chat with one
entity, high quality app, unique" became a whole rubric.

## Veto row

For a climb about a feeling. `Grounded` was: "no serif or second typeface, gradients, coloured
light, floating text or content centred in empty space. A fix that lowers this loses, however
much it raises the others."
