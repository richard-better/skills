# Health records

Builds and maintains a **records folder** from health PDFs. Each PDF becomes a **document**: a
faithful Markdown transcription with frontmatter. Every lab result becomes one row of
`markers.csv`, named consistently across labs and languages. `index.md` is generated from both
and is where any reader, such as the `differential-panel` skill, starts.

`<skill>` below is this skill's folder. Both scripts run with `uv run` and install their own
dependencies.

## The records folder

```
<records>/
  index.md        generated by records.py index; never edit by hand
  context.md      written by the owner: age, sex, conditions, medications with dates, questions
  markers.csv     one row per lab result; written only by records.py merge
  aliases.csv     this folder's original name -> canonical name pairs; grows during merges
  documents/
    2025-03-14_lab_example-lab.pdf    copy of the original
    2025-03-14_lab_example-lab.md     its transcription
  panels/         differential-panel reports
```

Document basenames are `YYYY-MM-DD_<type>_<provider-slug>`, with `-2`, `-3` added when two share
a name. The originals stay where they were; the folder holds copies.

### Document frontmatter

```yaml
---
date: 2025-03-14          # sample collection or visit date, not the print date
type: lab                 # lab | imaging | discharge | visit | pathology | procedure | prescription | vaccination | other
provider: Example Lab     # lab, hospital or practice as printed
title: Chemistry and blood count
clinician: Dr. Jane Doe   # optional
language: hu              # ISO 639-1 code of the original
source: 2025-03-14_lab_example-lab.pdf
sha256: <from extract.py's meta.json>
extraction: text          # text | vision | mixed: how the content was read
summary: Fasting glucose high (6.4), ferritin low (18), mild microcytic anaemia.
---
```

The summary is one English line naming what a clinician would look at first. The body follows.

### markers.csv

One row per result, sorted by name, then date:

| Column | Holds |
| --- | --- |
| `name` | Canonical name from `<skill>/references/analytes.csv`, or a new English name |
| `loinc` | LOINC code, filled from the analyte table when the unit matches; empty when unsure |
| `date` | Sample collection date, `YYYY-MM-DD` |
| `value` | As printed, with a decimal dot: `6.4`, `<0.5`, `>90`, `negative` |
| `unit` | As printed: `mmol/l`, `G/l`, `ug/l` |
| `ref_range` | `3.9-6.0`, `<5.2`, `>90`, or the printed text when it is neither |
| `flag` | `H`, `L`, `HH`, `LL` (critical), `A` (abnormal, no direction), or empty |
| `original_name` | The test name exactly as printed |
| `source` | The document: `documents/2025-03-14_lab_example-lab.md` |

CSV, not YAML or JSON: one line per result appends and diffs cleanly, `grep '^Ferritin,'`
prints a trend, and pandas, DuckDB and spreadsheets read it as is.

## Steps

### 1. Find the folders

Get the PDF folder and the records folder from the owner. For a new records folder, create
`documents/`, and ask the owner for the facts `context.md` needs (age, sex, conditions,
medications and supplements with start and stop dates, current questions). Write only what they
give.

### 2. Extract

```bash
uv run <skill>/scripts/extract.py <pdf-folder> --out <scratch>/extract --records <records>
```

`--records` skips PDFs already in the folder, by content hash. Each PDF gets a work folder with
`page-NNN.txt`, page images where needed, and `meta.json`. Each page's verdict says how to read
it:

- `text`: read the `.txt`. When a table's columns come out scrambled, open the page image too
  (rerun that PDF with `--images all`).
- `scan`: read the `.png` with your own vision. Read every number twice, against its row.
- `text+image`: read both; the image may carry content the text layer lacks.

A `FAIL` line is an encrypted or broken PDF. Carry it to the report; for an encrypted one, ask the
owner for an unlocked copy.

### 3. Transcribe each document

Write `documents/<basename>.md` and copy the PDF beside it as `<basename>.pdf`. The body is a
**faithful** transcription:

- Original language and wording. Every test, value, unit, flag, range, date, finding and
  conclusion, exactly as printed, typos included. Lab tables become Markdown tables.
- Leave out page furniture: repeated headers and footers, barcodes, page numbers.
- Replace national ID, insurance and passport numbers with `[ID]`. Keep the name and birth date.
- Mark what you cannot read `[illegible]`, never a guess.

Done when every PDF in step 2 has its document or a `FAIL` reason, and each document's
frontmatter is complete.

### 4. Stage and merge the markers

For every document with lab results, including results quoted in discharge letters, write one
row per result to `<scratch>/rows.csv` with the columns `original_name, value, unit, ref_range,
flag, date, source`. Add `name` for a test the analyte table does not know, or where the table's
name is wrong for this report: a method-specific test, or a D3-only vitamin D. A `name` that
differs from `aliases.csv` corrects the alias for later runs.

- Convert decimal commas to dots in `value` and `ref_range`; the merge refuses commas because
  only you know the document's locale.
- Map the report's flag column to the flag codes: `+`, `↑`, `H` to `H`; `-`, `↓`, `L` to `L`; `*`
  to `A`. A qualitative result (`positive`, `negatív`, `++`) is the `value`, never a flag; flag it
  `A` only when the report marks it abnormal. Leave the flag empty when the report prints none;
  the merge computes it from a numeric range.
- Use the sample's collection date. A report with several draws gets one row per draw.
- Blood is the default specimen. Prefix any other: `Urine protein`.

```bash
uv run <skill>/scripts/records.py merge <records> <scratch>/rows.csv
```

A document's rows replace all its earlier rows, so re-merging a corrected document is safe; add
`--clear <source>` for a corrected document that now has no results at all. When
the merge rejects rows, it writes nothing; fix them and rerun until it exits 0. For an unknown
test, choose the canonical English name a clinician would search for, keeping a units-specific
name like `Neutrophils %` apart from `Neutrophils`. The merge records it in `aliases.csv`. To find
its LOINC, search by analyte name only: `https://clinicaltables.nlm.nih.gov/api/loinc_items/v3/search?terms=<analyte>&df=LOINC_NUM,LONG_COMMON_NAME`;
pick the code whose property matches the unit (Moles/volume for mmol/L, Mass/volume for mg/dL)
and whose method matches the report, and pass it in a `loinc` column. The analyte table leaves
LOINC empty where the code depends on the method, such as eGFR.

Read the merge's notes: a flag the report and the range disagree on, a unit unusual for the
name, or one analyte with two values on one day usually means a misread or a wrong name. Check
those against the page. A result two documents both report stays in each; trends count it once.

### 5. Index and check

```bash
uv run <skill>/scripts/records.py index <records>
uv run <skill>/scripts/records.py check <records>
```

Done when `check` exits 0 and, for each document, its lab tables and `markers.csv` hold the same
number of results (`grep -c` the source path). Warnings for units or missing LOINC can stay;
mention them in the report.

### 6. Report

Tell the owner: documents added (date, type, provider, summary), PDFs skipped and why, flagged
results, and `check` warnings. Name results that moved across the reference range since their
previous value.

## Reading the folder

- `records.py table <records>` prints every analyte's full history, oldest first, as one
  Markdown table; `--name ferr` narrows it.
- Units are never converted. When an analyte appears in two units, `check` says so; compare
  those values with care.
